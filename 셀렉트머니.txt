가족 가계부 앱 – 은행 선택 기반 알림 파싱 요구사항 (TXT)

1. 핵심 컨셉
- 모든 금융 알림을 무조건 파싱하지 않는다.
- 사용자가 “원하는 은행만 선택”하면,
  선택된 은행의 알림만 가계부에 자동 기록한다.
- 선택되지 않은 은행 알림은 완전히 무시한다.

2. 은행 선택 방식 (하드코딩 아님)
- 앱 내부에는 여러 은행의 알림 파싱 규칙이 등록되어 있을 수 있다.
- 실제 동작 여부는 사용자 설정에 따라 결정된다.
- 은행 수 제한 없음 (사용자가 1개든 3개든 선택 가능)

설정 화면 예시:
[✓] KB국민은행
[ ] 신한은행
[ ] 카카오뱅크
[ ] 우리은행

문구:
“알림을 자동으로 인식할 은행을 선택하세요.
선택한 은행의 입·출금 알림만 가계부에 기록됩니다.”

3. 기술 요구사항 – 알림 파싱 조건
- Android NotificationListenerService 사용
- 아래 조건을 모두 만족할 때만 파싱 수행

조건:
1) notification.packageName 이
   사용자가 선택한 은행의 packageName 목록에 포함될 것
2) 알림 텍스트에 금액 정보가 포함될 것
3) 입금/출금/결제 키워드가 식별될 것

선택되지 않은 은행:
- 알림 수신은 되더라도
- 가계부 로직에는 절대 진입하지 않음

4. 은행 파싱 구조 (확장 가능 설계)
- 은행별 파싱 로직은 if/else 하드코딩 금지
- Config 기반 구조로 분리

예시 개념:
BankConfig {
  bankId
  displayName
  packageNames[]
  incomeKeywords[]
  expenseKeywords[]
  amountRegex
}

- 은행 추가 시:
  코드 수정이 아닌 Config 추가 방식이 이상적

5. 입금/출금 처리
- 입금도 반드시 파싱 대상에 포함
- 기본적으로는 KB 계좌 기준
- 추후 사용자별로 다른 은행 선택 가능

6. 사용자/관계 설계 (중요)
- “남편/아내” 개념 사용 금지
- 성별, 관계 표현 없음
- 사용자 ID 기반 구조

예:
User A
User B

- 사용자 이름은 자유 설정
- 싱글 사용자도 사용 가능
- 공유 가계부는 사용자 추가 방식으로 처리

7. 계좌 분리 및 합산
- 사용자별로 입·출금 내역 분리 가능
- 전체 합산 보기 가능
- 사용자 필터:
  [전체] [사용자1] [사용자2]

8. 고액 결제 예외 처리
- 100만 원 초과 금액 감지 시
  자동 저장하지 않음
- 사용자에게 확인 팝업 표시

예:
“1,230,000원이 감지되었습니다.
이 항목을 가계부에 저장할까요?”

- 말일 카드 청구 총액 등 자동 포함 방지 목적

9. 알림 텍스트 수동 입력 기능
- 알림 접근 권한이 없거나
- 파싱 실패 시를 대비하여
  알림 텍스트 복사/붙여넣기 입력 기능 제공

동작:
- 사용자가 알림 내용을 붙여넣으면
- 자동 알림 파싱과 동일한 로직으로 처리

입력 소스 구분:
- Notification
- Manual Text Input

10. 알림 소스
- 카카오 알림톡
- KB국민은행 앱 알림
- KB Pay 알림

→ 알림 형식 차이는 파싱 규칙으로 처리

11. 목표 UX
- 사용자가 “왜 이 항목이 들어왔지?”라고 느끼지 않게 할 것
- 내가 선택한 은행의 실제 입·출금만 기록되는 가계부
- 가족/커플/싱글 모두 거부감 없이 사용 가능
