0. 핵심 운영 정책 (Policy)
================================================================================

┌──────────────────────────────────────────────────────────────────────────────┐
│ [정책 1] Default 운영 정책 - 보수적 접근                                     │
└──────────────────────────────────────────────────────────────────────────────┘

▶ 초기 운영 철학
  - 목표: "미분류를 줄이는 것"보다 "오탐 없이 안정적으로 저장"
  - 자동 확정은 보수적으로 (confidence ≥ 0.75)
  - 애매하면 반드시 "검토함" 또는 "사용자 선택"으로 넘김
  - 잘못된 자동 분류보다 사용자에게 물어보는 것이 더 나음

▶ Confidence 기준
  - ≥ 0.75 : 자동 확정 (높은 확신)
  - 0.50 ~ 0.75 : 자동 저장 + "검토 필요" 배지 (중간 확신)
  - < 0.50 : 폴백 UX 표시 (낮은 확신, 사용자 개입 유도)


┌──────────────────────────────────────────────────────────────────────────────┐
│ [정책 2] 미분류(null merchant) 허용 정책                                     │
└──────────────────────────────────────────────────────────────────────────────┘

▶ 원칙: 억지로 넣지 말고 미분류 허용
  - 사용처를 못 잡으면 merchant = null 또는 "미분류"로 저장
  - 이후 사용자 수정으로 학습하여 재발 방지
  - null merchant는 "정상 상태"로 허용됨 (에러 아님)

▶ 미분류 처리 흐름
  1. 파싱 실패 또는 confidence < 0.50 → merchant = null
  2. "검토함" 탭에 거래 표시
  3. 사용자가 수정 시 → LearnedRule 저장
  4. 동일 패턴 재발생 시 → 학습된 merchant 자동 적용


┌──────────────────────────────────────────────────────────────────────────────┐
│ [정책 3] LearnedRule 우선순위 규칙                                           │
└──────────────────────────────────────────────────────────────────────────────┘

▶ 우선순위 (높음 → 낮음)
  1. User-confirmed LearnedRule (사용자가 직접 수정/확정한 룰)
  2. Signature-based LearnedRule (자동 학습된 패턴 기반 룰)
  3. Heuristic parsing (N-best 후보 추출 + 점수화)

▶ 충돌 해결 규칙
  - 동일 signature에 복수 룰 존재 시: updatedAt이 최신인 것 우선
  - 사용자 확정 룰은 자동 룰을 덮어씀
  - hitCount가 높을수록 신뢰도 가점 (+0.05 per 10 hits, max +0.1)


┌──────────────────────────────────────────────────────────────────────────────┐
│ [정책 4] 사용처 파싱 ↔ 카테고리 분류 분리 원칙                               │
└──────────────────────────────────────────────────────────────────────────────┘

▶ 분리 이유
  - 사용처 파싱과 카테고리 분류는 독립적으로 동작
  - 사용처가 흔들리면 카테고리도 흔들린다
  - 따라서 사용처 파싱이 먼저 안정되어야 카테고리 품질이 올라감

▶ 처리 순서
  1단계: 사용처 파싱 (merchant 추출)
  2단계: 사용처 정규화 (normalization)
  3단계: 카테고리 분류 (merchant → category)

▶ 의존성
  - 카테고리 분류는 merchant가 확정된 후에만 실행
  - merchant = null이면 category = "미분류"
  - 사용처가 수정되면 카테고리도 재분류 트리거


┌──────────────────────────────────────────────────────────────────────────────┐
│ [정책 5] 성공 지표(KPI) 정의                                                 │
└──────────────────────────────────────────────────────────────────────────────┘

▶ Success Metrics (목표)

  1. 자동 확정 비율 (Auto-confirm Rate)
     - 목표: ≥ 70%
     - 정의: confidence ≥ 0.75인 거래 / 전체 거래 × 100

  2. 폴백 발생률 (Fallback Rate)
     - 목표: ≤ 20%
     - 정의: confidence < 0.50인 거래 / 전체 거래 × 100

  3. 사용자 수정 후 재발 방지율 (Learning Effectiveness)
     - 목표: ≥ 90%
     - 정의: 동일 패턴 재발생 시 학습된 merchant 적용 성공 비율

  4. 미분류 비율 (Unclassified Rate)
     - 목표: ≤ 10%
     - 정의: merchant = null인 거래 / 전체 거래 × 100

  5. 오분류율 (Misclassification Rate)
     - 목표: ≤ 5%
     - 정의: 사용자가 자동 분류된 merchant를 수정한 비율

▶ 후보 추출 패턴 (정규식)

1) 라벨 기반 후보 (가장 강함)
   - 정규식: (가맹점|사용처|매장|상호)\s*[:：]\s*([^\n]+)

2) 금액 주변 후보
   - 금액 라인에서 숫자/키워드 제거 후 잔여 텍스트
   - 인접 라인(위/아래)에서 2~40자 텍스트

3) 상단 라인 후보
   - 첫 1~2줄에서 2~40자 텍스트

▶ 스코어링 규칙

[감점 규칙]
- 길이가 2~40자 범위 밖: -2.0
- 금액 패턴 포함: -3.0
- 6자리 이상 연속 숫자 포함: -2.5
- BAD_TOKENS 2개 이상 포함: -2.0
  BAD_TOKENS = ["승인", "취소", "완료", "정기", "자동이체", "잔액", "한도",
                "카드", "계좌", "번호", "TID", "MID", "TEL", "고객센터",
                "사업자", "입금", "출금", "송금"]
- 숫자 비율 > 35%: -1.5

[가점 규칙]
- 글자(한글/영문) 2자 이상 포함: +1.0
- 상호 힌트 포함: +0.8
  힌트 = ["점", "지점", "스토어", "마켓", "카페", "마트", "약국", "병원", "주유"]

[출처 가중치]
- LABEL_AFTER: +1.5
- NEAR_AMOUNT: +0.8
- FIRST_LINES: +0.4
- HEURISTIC_BLOCK: +0.2

fun normalizeMerchant(raw: String): String {
    return raw
        // 괄호 내용 제거: ( ... )
        .replace(Regex("""\([^)]*\)"""), " ")
        // 법인 표기 제거: (주), 주식회사, (유), 유한회사
        .replace(Regex("""(주식회사|\(주\)|유한회사|\(유\))"""), " ")
        // TID/MID/TEL 제거
        .replace(Regex("""(TID|MID|TEL)\s*[:：]?\s*\S+""", RegexOption.IGNORE_CASE), " ")
        // 전화번호 패턴 제거: 000-0000-0000
        .replace(Regex("""\d{3}-\d{4}-\d{4}"""), " ")
        // 긴 숫자 제거 (6자리 이상)
        .replace(Regex("""\d{6,}"""), " ")
        // 지점명 제거: OOO점, #1234
        .replace(Regex("""[가-힣a-zA-Z]+점(?=\s|$)"""), " ")
        .replace(Regex("""#\d+"""), " ")
        // 다중 공백 정리
        .replace(Regex("""\s+"""), " ")
        .trim()
}

▶ 플랫폼/PG 처리

- 패턴: 네이버페이/OOO커피 → OOO커피 우선
- 슬래시/하이픈 분리 후 더 상호 같은 쪽 선택
- 플랫폼 목록: 네이버페이, 카카오페이, 토스, 쿠팡페이, 이니시스, KCP

fun confidence(best: Double, second: Double?, hasAmount: Boolean): Double {
    val s2 = second ?: (best - 2.0)
    val margin = best - s2
    var c = 0.4
    c += (best / 6.0).coerceIn(0.0, 0.4)
    c += (margin / 4.0).coerceIn(0.0, 0.3)
    if (hasAmount) c += 0.1
    return c.coerceIn(0.0, 1.0)
}

▶ 신뢰도 기준 (UX 분기)

- confidence >= 0.75 : 자동 확정 저장
- 0.50 ~ 0.75 : 자동 저장 + "검토 필요" 배지
- < 0.50 : 폴백 UX (사용자 선택 유도)

▶ 지원 패턴

1. MM/dd HH:mm (예: 01/20 14:03)
   - 정규식: (?<!\d)(\d{1,2})[./-](\d{1,2})\s+(\d{1,2}):(\d{2})(?!\d)

2. yyyy-MM-dd HH:mm / yyyy.MM.dd HH:mm
   - 정규식: (?<!\d)(\d{4})[./-](\d{1,2})[./-](\d{1,2})\s+(\d{1,2}):(\d{2})(?!\d)

3. HH:mm만 있는 경우
   - 날짜는 receivedAt의 날짜 사용
   - 정규식: (?<!\d)(\d{1,2}):(\d{2})(?!\d)

4. 상대 표현
   - 오늘 HH:mm, 어제 HH:mm

▶ 안전 장치

- 숫자 앞뒤 경계(lookaround)로 승인번호 오인 방지
- receivedAt 대비 ±45일 범위 벗어나면 무효
- HH:mm만 있을 때 "일시|시간|승인" 라벨 근접도 체크
- "잔액" 주변의 시간은 감점

▶ Signature 생성

fun signatureOf(clean: String, raw: RawMessage): String {
    val base = (raw.pkg ?: raw.sender ?: "unknown") + "|" +
        clean.replace(KRW_AMOUNT, " ")
             .replace(Regex("""\d+"""), " ")
             .replace(Regex("\\s+"), " ")
             .take(40)
    return base.lowercase()
}

▶ Merge Key 생성

fun mergeKey(
    amount: Long,
    isCancel: Boolean,
    approxTime: Long,
    windowSec: Long,
    channelHint: String?
): String {
    val bucket = (approxTime / 1000L) / windowSec
    val hint = channelHint?.lowercase()?.take(64) ?: "unknown"
    return "a=$amount|c=$isCancel|b=$bucket|h=$hint"
}

▶ 병합 로직

1. rawHash로 Observation 중복 제거
2. 느슨한 매칭: amount + isCancel + 시간 ±180초
3. 후보 중 confidence 높은 쪽에서 merchant 채택

5. 핵심 정규식 패턴 모음
================================================================================

▶ 금액 패턴
(\d{1,3}(?:,\d{3})+|\d+)\s*원

▶ 라벨 기반 가맹점
(가맹점|사용처|매장|상호)\s*[:：]\s*([^\n]+)

▶ 날짜 시간 패턴
(?<!\d)(\d{1,2})[./-](\d{1,2})\s+(\d{1,2}):(\d{2})(?!\d)
(?<!\d)(\d{4})[./-](\d{1,2})[./-](\d{1,2})\s+(\d{1,2}):(\d{2})(?!\d)
(?<!\d)(\d{1,2}):(\d{2})(?!\d)

▶ 전화번호
01\d[- ]?\d{3,4}[- ]?\d{4}

▶ 긴 숫자 (계좌/카드)
(?<!\d)\d{10,19}(?!\d)
(?<!\d)\d{2,6}-(\d{2,6}-){1,3}\d{2,6}(?!\d)

▶ 법인 표기
(주식회사|\(주\)|유한회사|\(유\))

▶ 부가 정보 제거
(TID|MID|TEL)\s*[:：]?\s*\S+
\d{3}-\d{4}-\d{4}
[가-힣a-zA-Z]+점(?=\s|$)
#\d+
